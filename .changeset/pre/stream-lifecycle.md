Fix several ways a stream's lifecycle could go wrong. `watch()` whose join answer arrives while the request is still being sent now returns the live view instead of throwing and leaving it with no handle. A request that never left the flood throttle is no longer withdrawn, and a failed withdrawal is reported on the `error` event instead of being swallowed. A stream the server answers a join request for with 5635 ("Stream does not exist") is ended locally with the cause `"gone"` and leaves `list()`. A `publish()` whose stream was stopped before its own answer arrived rejects with a `StreamEndedError` instead of adopting a dead stream. A viewer lookup answers for its own request, so a reused client id can no longer announce the wrong viewer, and lookups for requesters out of view run side by side (at most eight at once) while requests are still announced in the order they came. Stream numbers on the wire (`type`, `accessibility`, `mode`, the stop `reason`) are read as unsigned 32-bit numbers and an ICE candidate's `mLine` as an unsigned 16-bit one, as the Go SDK does; anything else is ignored. `CommandOptions` gains `onSent`, called once the command has left the flood throttle.
